# Environment and Secrets

> Status: proposed (planning). Last updated 2026-10-02.

## Rules

1. **Never commit secrets.** `.env` is git-ignored; only `.env.example` (names, no values) is
   committed. Check `git status` and the staged diff before every commit.
2. **No secrets in config files.** MCP config uses `${VAR}` placeholders resolved at runtime.
3. **No secrets in the renderer, logs, run traces or LLM prompts.** Mask keys in logs
   (`sk-...abcd`).
4. **One key per purpose.** Don't reuse the voice-agent keys for Agent2DB in the long run;
   create separate provider keys so they can be revoked independently.
5. **Rotate on exposure.** Any key pasted into chat, logs or a screenshot is considered exposed.

## Development (now)

- Local values live in `.env` at the repo root, loaded by the backend only.
- `.env.example` lists every variable the project reads.
- Recommended: add a pre-commit secret scanner (e.g. `gitleaks`) once the repo is initialised.

## Production (desktop app)

- Provider keys and DB passwords are entered in Settings and stored with Electron `safeStorage`
  (OS keychain / DPAPI on Windows).
- Electron main passes them to the backend as environment variables at spawn; they are never
  written to disk in plain text.

## Variables

| Variable | Used by | Notes |
|---|---|---|
| `POSTGRES_HOST/PORT/DB/USER/PASSWORD`, `DATABASE_URL` | backend (app DB) | dev container |
| `AGENT2DB_RO_DSN` | `postgres-read` MCP server | role `agent2db_ro` |
| `AGENT2DB_RW_DSN` | `postgres-write` MCP server | role `agent2db_rw` |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `XAI_API_KEY` | LiteLLM | set only the providers you use |
| `AGENT2DB_PORT`, `AGENT2DB_TOKEN` | backend | generated by Electron per launch, not in `.env` |
